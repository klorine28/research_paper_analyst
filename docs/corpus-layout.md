# Corpus directory layout

Every pipeline stage reads and writes inside one **Corpus** directory. The
layout is a convention, not configuration: point the tool at the directory and
it knows where everything lives.

```text
<corpus>/
  corpus.bib          # the paper list: a BibTeX file, or dois.txt (one DOI per line)
  papers/             # the Papers' PDFs, and nothing else
  paper-data/         # per-Paper derived data (parsed sections, Extractions, LLM cache)
  artifacts/          # stage outputs (ingest -> extract -> aggregate -> detect)
  judgments/          # accept/reject decisions and chat history (persist across runs)
```

## Rules

- **Paper list at the root.** Either a BibTeX file (`*.bib`) or a plain DOI
  list named `dois.txt`. If both exist, the BibTeX file wins; with several
  `.bib` files, the first in alphabetical order is used.
- **`papers/` holds only PDFs.** Anything else there is misplaced: derived
  data belongs in `paper-data/`. PDF file names are free-form; ingest matches
  them to paper-list entries (see ticket [03]).
- **Derived data is disposable.** `paper-data/` and `artifacts/` can be
  deleted and regenerated by re-running stages. `judgments/` cannot: it holds
  the researcher's own decisions.
- **A Corpus holds 10–75 Papers.** The envelope is enforced by ingest, not by
  the layout check.

## Artifacts

| File | Written by | Holds |
| --- | --- | --- |
| `artifacts/corpus-manifest.json` | `ingest` | One record per Paper (citation key, DOI, title, authors, year, journal, PDF path), plus the paper-list entries with no PDF and the PDFs with no entry |

## Checking a directory

```python
from pathlib import Path

from research_gap_dashboard.corpus_layout import inspect_corpus_layout

report = inspect_corpus_layout(Path("corpora/cardiology"))
if not report.is_valid:
  for problem in report.problems:
    print(problem.kind, problem.path, problem.message)
```

`inspect_corpus_layout` reports what is present, missing, or misplaced; it
never creates, moves, or deletes anything. `report.paper_list_path` and
`report.pdf_paths` give later stages the inputs they need, and
`report.layout` exposes the four directory paths.
